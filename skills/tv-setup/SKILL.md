# Настройка Android TV по tv-setup

Ты работаешь с настоящим устройством пользователя. Каждый шаг проверяй на ТВ: вывод команды, `dumpsys`,
скриншот через `tools/tv.py --screenshot`. Перед первым изменением прочитай правила безопасности в
[`AGENTS.md`](../../AGENTS.md), раздел «Cleaning a TV». Коротко:

- только `pm disable-user`, без удаления;
- без root и прошивок;
- сначала резерв;
- не трогать то, без чего ТВ не работает;
- стоковый лаунчер отключать только после того, как новый стал Home.

Скрипты в `tools/` эти правила уже соблюдают — используй их, а не свои команды.

**Спроси у пользователя только две вещи** (шаг 4):

1. город — для времени намаза;
2. какие приложения ему не нужны.

Всё остальное делай сам и объясняй по ходу, коротко, по-русски.

## Шаги

Каждый шаг можно запустить повторно, уже сделанное он не ломает. Если пользователь вернулся к настроенному ТВ,
пройди шаги заново: где всё на месте, шаг сообщит об этом и ничего не изменит.

### 0. Подготовка компьютера

```sh
python3 -m venv tools/venv && tools/venv/bin/pip install -r tools/requirements.txt
```

Для сборки лаунчера нужны JDK 17 и Android SDK (platform 34, build-tools 34). Если их нет — скажи, что поставить.
`launcher/build-and-install.sh` сам ищет JDK 17 и SDK в стандартных местах. ByeByeDPI проверяется `apksigner` из
build-tools.

### 1. Найти ТВ и подключить adb

Подробно — [`references/connect.md`](references/connect.md). Порядок:

- найти ТВ через mDNS (`_androidtvremote2._tcp`, `_adb-tls-connect._tcp`);
- если не нашёлся — спросить IP;
- провести пользователя по включению отладки на ТВ;
- попросить подтвердить ключ на экране ТВ;
- проверить: `TV_HOST=<ip> tools/venv/bin/python -I tools/tv.py --probe`.

Дальше во всех командах `TV_HOST=<ip>`. IP нигде не записывай: ни в файлы репо, ни в коммиты.

### 2. Резерв

```sh
TV_HOST=<ip> tools/tv-backup.sh
```

Скрипт пишет снимок в `backup/<модель>-<время>`. Первый снимок ТВ сохраняется как `backup/original-<модель>`,
и повторные запуски его не трогают — это точка отката для `tools/tv-restore.sh`. Папка `backup/` в `.gitignore`:
там серийники и имена сетей, наружу она не уходит.

### 3. Осмотр

```sh
TV_HOST=<ip> tools/venv/bin/python -I tools/tv.py 'getprop ro.product.model; getprop ro.build.version.sdk; getprop ro.product.cpu.abi'
TV_HOST=<ip> tools/venv/bin/python -I tools/privacy.py
```

- **SDK ниже 26:** лаунчер не встанет. Скажи об этом и остановись на шагах без лаунчера (5, 7, 8).
- **Готовый список:** поищи проверенный список для этой модели в [`examples/`](../../examples/README.md) (по
  `ro.product.model`, например `xiaomi-mitv-aesp0` для Mi TV Stick).

### 4. Два вопроса пользователю

**Город.** Если это город или район Дагестана — возьми готовую таблицу муфтията: slug из
[`prayer-tables/index.json`](../../prayer-tables/index.json) (`makhachkala`, `derbent`, `khasavyurt` и т. д.).

Любой другой город — сгенерируй таблицу:
- координаты и IANA-пояс подставь сам по названию;
- метод спроси, только если пользователь его знает. По умолчанию `mwl`; для России обычно `russia` (ДУМ РФ),
  для Саудовской Аравии `umm-al-qura`.

```sh
tools/prayer_table.py --city kazan --name "Казань" --lat 55.7963 --lon 49.1088 --tz Europe/Moscow --method russia
```

Честно скажи пользователю: расчёт по формуле может расходиться с расписанием местной мечети на несколько минут
(таблица расхождений — [`docs/tv-setup/prayer-times.md`](../../docs/tv-setup/prayer-times.md)). Если у мечети
есть своя таблица, лучше положить её в `prayer-tables/` в том же формате. Город без намаза — тоже ответ: тогда
`PRAYER_CITY` не задаётся.

**Ненужные приложения.** Покажи установленное по категориям из
[`references/apps.md`](references/apps.md):

- телеметрия и реклама — «рекомендую отключить»;
- стоковый лаунчер — «отключится сам после установки нового»;
- голосовой ассистент, Chromecast, трансляция, стрим-сервисы, обновление прошивки — «нужно ли вам?»;
- системное — не трогаем и не показываем.

Возьми ответ пользователя, проверенный список модели из `examples/` и отчёт `privacy.py`. Собери из них
`backup/<модель>-debloat.txt` (один пакет в строке, с комментарием-причиной).

### 5. Отключить выбранное

```sh
TV_HOST=<ip> tools/disable.sh backup/<модель>-debloat.txt
```

- Отключает по одному пакету через `pm disable-user` и сам отказывается трогать системные пакеты.
- Перед первым изменением пишет свою запись состояния. Откат: `tools/restore.sh` с тем же списком.
- Уже отключённые пакеты повторный запуск пропускает.
- Полное удаление (`pm uninstall --user 0`) — только если пользователь прямо попросил. Тогда назови пакет
  и предупреди, что вернуть его можно `cmd package install-existing`.
- Отключай небольшими порциями, со скриншотом между ними.

### 6. Лаунчер

Флаги и проверка — [`references/launcher.md`](references/launcher.md). Команда целиком (из корня репо):

```sh
PRAYER_CITY=<slug> HOME_KEY_SERVICE=1 PRAYER_OVERLAY=1 VPN_PILL=1 USAGE_DOCK=1 SLEEP_TIMER=1 PRAYER_DREAM=1 \
  TV_HOST=<ip> launcher/build-and-install.sh
```

- **Повторно** можно ставить поверх: `pm install -r`. Флаги передавай каждый раз — Android выключает
  accessibility-помощник при переустановке.
- **Хиджра** включена в конфиге, отдельного флага нет.
- **`PRAYER_DREAM=1`** печатает прежнюю заставку — запиши её в отчёт пользователю.
- **Кнопка Home:** проверь настоящим пультом, а не `input keyevent`. На многих Xiaomi Home приходит как
  `KEYCODE_ALL_APPS` и работает только через `HOME_KEY_SERVICE`.

### 7. ByeByeDPI для YouTube

Подробно — [`references/byedpi.md`](references/byedpi.md).

```sh
TV_HOST=<ip> tools/byedpi.sh
```

Скрипт:
- скачивает релиз под ABI приставки;
- сверяет SHA-256 с релизом и сертификат подписи с авторским;
- ставит приложение, если этой версии ещё нет;
- задаёт стратегию;
- кладёт на ТВ файл настроек: белый список только `com.google.android.youtube.tv`, системный DNS, автозапуск;
- выдаёт согласие на VPN через `appops`, чтобы системный диалог не появлялся.

Дальше **всё делаешь сам**, без пульта: импорт файла настроек через меню ByeByeDPI кнопками/тапами adb по
скриншотам, затем «Подключить» и проверка, что YouTube играет через `tun0`. Пошагово и запасной ручной путь — в
reference. Пользователя к пульту не отправляй.

Стратегия подобрана под одного провайдера и может не сработать у другого — так и скажи. Как подобрать свою —
в reference.

### 8. Мелочи

```sh
TV_HOST=<ip> tools/tv-tweaks.sh             # анимации 0.5, очистка кешей
TV_HOST=<ip> LOCATION_OFF=1 tools/tv-tweaks.sh   # и геолокация выключена — только если пользователь хочет
```

Предупреди: без геолокации Android 8+ не отдаёт имя Wi-Fi-сети, и пилюля Wi-Fi покажет просто «Wi-Fi».

### 9. Проверка и завершение

- **Скриншот главного экрана:** часы, дата и хиджра, капсула намаза, пилюли Wi-Fi/Настройки и VPN/Сон, док.
- **Пульт:** Home возвращает на главный экран; намаз-плашка:
  `am broadcast -n com.gathin.tvhome/.PrayerNotice\$Shell` поверх YouTube.
- **YouTube** играет через ByeByeDPI.
- **Отчёт пользователю:**
  - что отключено;
  - прежняя заставка;
  - как откатиться: `TV_HOST=<ip> tools/tv-restore.sh backup/original-<модель>` и/или `tools/restore.sh <список>`.
- **Отладка:** посоветуй выключить ADB-отладку в настройках разработчика и отозвать ключи. Проверка, что порт
  закрыт: `tools/venv/bin/python -I tools/adb-closed.py <ip>`. Порт 5555 открытый, без шифрования.

## Если что-то пошло не так

- **ТВ перестал отвечать по adb после включения VPN** — переподключись: `adb connect` или повторный запуск команды.
  ByeByeDPI с белым списком сеть adb не трогает, но первое переключение может оборвать соединение.
- **Home ведёт не туда** — `launcher/build-and-install.sh` сам откатывает Home, если новый лаунчер не стал Home.
  Не используй `FORCE_HOME` без согласия пользователя.
- **Всё вернуть** — `tools/tv-restore.sh backup/original-<модель>` (есть `--dry-run`, чтобы сначала посмотреть план).
